## ③ 对 REVIEW-A 的反驳

### C-1：A-1 把「有确定答案」误判为「未定义」
- **问题描述**：A-1 称失败后「计划没有说明此时算完成还是未收口」。但完成标志首句即「5 个文件全部存在且内容符合各自验收标准」——某项 failed 则对应文件不存在，合取式为假，结论唯一：**未收口**。这不是矛盾，是确定语义。「跳过继续」约束的是**执行顺序**（不因一项失败而中止后续），「完成标志」定义的是**终局判定**，二者作用在不同对象上，A 强行让它们在同一处求值。

## ⑤ A 与 B 之间的互斥修法（采纳任何一套都会踩到另一套）

| 冲突点 | A 的修法 | B 的修法 | 对抗轮裁定 |

| 校验值长度 | 前 16 位截断 | 64 位全 hex + 补零 | 二者互斥，不可同采；且 B 的「补零」对定长摘要无效 |
| 失败态的整体判定 | 任一项 failed ⇒ 未完成，须补做 | ≥4 项 done ⇒ 完成 | **采纳 A**。B 的方案降门槛且会造出「内容为真值判断为假」的 summary.txt |
| 预存在文件的处理 | 记录原哈希并**中止** | 未涉及 | **驳回 A 的中止分支**，与 A-6 的恢复方案互斥 |

两轮独立审查在 4 处收敛（A-1↔B-H2/H4、A-2↔B-H1、A-3↔B-M5、A-4/A-5↔B-L12），但收敛处给出的修法三度互斥。**收敛不等于共识**：17 条发现不能按条数累加权重，去重后真实缺口为 5 条（见 ⑦）。

## ⑥ A 与 B 共同遗漏的缺口

### C-14：验收项 5 的内容串是状态断言，与「失败跳过」存在语义冲突（双方均遗漏）
- **问题描述**：`summary.txt` 的内容固定为 `all five items done`，这是一个**对整体状态的断言**，而非中性文本。PLAN 的失败处置允许某项 failed 后跳过继续，却没有禁止在这种情况下继续写出 summary.txt。于是存在一个 PLAN 未排除的状态：前序项失败、summary.txt 已写出、其内容串与验收标准**逐字匹配**、验收项 5 判定通过，而文件陈述的「五项全部完成」为假。A 审「失败路径是否被失败与回滚处置覆盖」却只看了回滚，没看内容语义；B 审「完整性」却只看了格式边界，没看内容真值。这是两条维度交叉处的盲区，恰恰是两轮独立审查最容易同时漏掉的类型。
- **影响验收项**：5（直接）、失败与回滚处置、完成标志
- **建议修法**：二选一并写进 PLAN——（a）规定 summary.txt 仅在前 4 项全部 done 后才允许写入，前序有 failed 时第 5 项直接记 `5|failed|前置项未完成`；（b）或把内容串改为中性文本（如 `stage 1 artifacts`），使其不承载状态断言。推荐 (a)，成本为零且不改动验收项。

### C-15：把校验值写死为 sha256 会新增「双写一致性」义务（双方均未预见，且由 A-2/B-H1 的修法亲手引入）
- **问题描述**：PLAN 中「PROGRESS.md 带校验值」与「STAGE-1.md 记各自 sha256」是**同一事实的两处留痕**。当前 PLAN 未强制二者同源，也就没有一致性义务。而 A-2 与 B-H1 都主张把校验值明确定义为 sha256——一旦照办，两份文件之间就凭空产生了「同一文件两处哈希必须相等」的新判据，而 PLAN 没有规定谁为准、不一致时如何处理。两轮的修法在收紧一处口径的同时，在另一处开出新缺口。
- **影响验收项**：完成标志（PROGRESS.md 与 STAGE-1.md 两条）、阶段收口约定 ①
- **建议修法**：若采纳 A-2/B-H1，必须同时写明「PROGRESS.md 与 STAGE-1.md 中同一产物的 sha256 须一致；不一致时以 STAGE-1.md 为准并重算 PROGRESS 对应行」。或不采纳该修法（对抗轮倾向后者）。

### C-16：两份收口文件自身不在回滚范围内，回滚后状态不可区分（A-5/A-6 的边界情形，双方均未点破）
- **问题描述**：「产物均为新建文件，删除即回滚」中的「产物」若按完成标志理解，应包含 PROGRESS.md 与 STAGE-1.md。但这两份文件正是记录「做过什么」的唯一依据——一旦回滚删除它们，系统将回到「无任何痕迹」的初始态，A-6 提出的「以 PROGRESS 为准恢复」立即失效，且无法区分「从未执行」与「执行后已回滚」。A-5 关注了误删用户文件，A-6 关注了中断恢复，都没注意到**回滚动作会销毁恢复所依赖的证据**。
- **影响验收项**：失败与回滚处置、完成标志（PROGRESS.md 一致性）
- **建议修法**：明确回滚范围仅含 5 项产物，PROGRESS.md 与 STAGE-1.md 保留并追加回滚记录行；或在回滚前将两份文件改名归档。
